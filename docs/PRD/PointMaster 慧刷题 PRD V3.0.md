## 文档信息

| 项 | 值 |
|---|---|
| 产品名称 | PointMaster 慧刷题 |
| 产品定位 | AI 知识图谱驱动的自适应刷题系统 |

---

## 1. 产品概述

### 1.1 产品简介

PointMaster 慧刷题是一款 **AI 知识图谱驱动的自适应刷题系统**。

V3.0 聚焦于**把刷题主线真正落地**：用户选择题库后，AI 分析知识图谱生成一条「知识点刷题顺序」，用户沿这条顺序逐个知识点推进，每个知识点做完后自主决定重刷、错题重刷或进入下一个。系统在右侧实时呈现算法驱动的掌握度分析，帮助用户随时了解自己「掌握到什么程度」。

**核心理念**：清晰的学习路径 + 用户掌控节奏 + 算法实时反馈。

### 1.2 V3.0 核心变化（对比 V2.0）

| 维度 | V2.0 | V3.0 |
|------|------|------|
| 练习模型 | Agent 每个 block 结束后自主路由决策 | 用户主导，按知识点顺序线性推进 |
| AI 决策角色 | 全程决策者（每步建议下一步） | 前期规划者（仅生成一次知识点排序） |
| 推进单位 | Block（Agent 动态决定题量/知识点） | Knowledge Point（一个知识点为一站） |
| 推进控制 | Agent 建议 + 用户覆盖 | 用户全程掌控，可提前跳到下一知识点 |
| 知识点排序 | Agent 运行时动态选择 | AI 一次性生成排序，用户可微调 |
| 自定义提示词 | 无 | 用户输入提示词影响初始排序（如「优先刷 xxx」） |
| 题型 | 客观 + 主观（LLM 判分） | 仅客观题（系统比对判分） |
| 微学习 | 主线环节（Agent 触发） | 保留入口，不在 3.0 主线展开 |
| 界面 | 做题页 / Agent 决策页分离 | 单页三区（知识点条 / 做题区 / 掌握度面板） |

### 1.3 与 V2.0 的关系

V3.0 是 V2.0 的**简化与聚焦版**，不是推翻。它砍掉了尚未落地、复杂度高的「Agent 自主分块路由」，换成用户更可控、更易实现的「知识点顺序刷题」主线。V2.0 中已实现的能力（题库导入、AI 知识点提取、知识图谱构建、微学习画布、划词问 AI）全部保留复用。Agent 路由决策作为远期能力封存，本 PRD 不实现。

## 3. 系统架构

### 3.1 三层架构

```
┌─────────────────────────────────────────────────────┐
│                  用户交互层                           │
│  刷题页（知识点条 / 做题区 / 掌握度面板） / 报告页    │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│                 AI 服务层                             │
│  知识图谱构建 / 知识点排序规划 / 单题问 AI            │
│  （LLM 调用点，非实时关键路径）                       │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│                算法 + 数据层                          │
│  选题 / 掌握度计算 / 置信度更新 / 完成判定 / 持久化   │
│  （确定性算法，零延迟，全程主导刷题）                 │
└─────────────────────────────────────────────────────┘
```

### 3.2 LLM 调用点（共 3 个，均非实时关键路径）

| 调用点 | 触发时机 | 输入 | 输出 |
|--------|----------|------|------|
| **知识图谱构建** | 题库导入处理时（已实现） | 题库题目 | 知识点 + 依赖关系 |
| **知识点排序规划** | 选完题库、开始刷题前 | 知识图谱 + 用户自定义提示词 | 知识点有序列表 + 排序理由 |
| **单题问 AI** | 某题提交后用户提问 | 题目 + 答案 + 解析 + 用户问题 | AI 解答 |

> 刷题过程中的选题、判分、掌握度更新、完成判定**全部由算法层完成，不调用 LLM**，保证做题流畅零延迟。

### 3.3 算法层职责（不用 LLM）

| 职责 | 说明 |
|------|------|
| 选题 | 在当前知识点题池内按策略选下一题（未做优先、错题重刷模式只选错题） |
| 判分 | 客观题系统比对，得 0/1 分 |
| 掌握度更新 | 每题作答后实时更新 mastery / confidence / streak |
| 完成判定 | 判断当前知识点是否达「完成」条件（达阈值或题目做完） |

## 4. 核心流程

### 4.1 端到端路径

```
① 选择题库
    ↓
② AI 分析知识图谱 → 生成知识点刷题顺序
    （用户可输入自定义提示词："我想优先刷 xxx"）
    （排序结果展示给用户，支持手动拖拽微调）
    ↓
③ 进入刷题页（单页三区布局）
    ↓
④ 在当前知识点内循环做题
    展示题目 → 作答 → 提交 → 显示答案与解析 →（可问 AI）→ 下一题
    ↓
⑤ 当前知识点「完成」（达掌握度阈值 或 题目全做完，先到为准）
    ↓
⑥ 弹出选择：[重新刷题] / [错题重刷] / [下一知识点]
    （允许在未完成时也提前进入下一知识点）
    ↓
⑦ 所有知识点处理完 → 掌握度报告
```

### 4.2 知识点排序规划

**触发**：用户选完题库、点击「开始刷题」时。

**输入**：
- 该题库的知识图谱（知识点 + `prerequisite_ids` 依赖关系）
- 用户自定义提示词（可选，自由文本，如「我想优先刷动态规划」「先把简单的过一遍」）

**排序原则**：
1. 默认遵循知识图谱的依赖关系（前置知识点排在依赖它的知识点之前）
2. 用户提示词作为**软约束**叠加在依赖关系之上（如「优先刷 xxx」会把 xxx 及其前置提前，但不破坏必要依赖）
3. 输出每个知识点的简短排序理由，便于用户理解

**输出**：
```json
{
  "ordered_knowledge_points": [
    { "id": "kp_1", "name": "变量与类型", "order": 1, "reason": "基础前置，无依赖" },
    { "id": "kp_2", "name": "循环结构", "order": 2, "reason": "依赖变量与类型" }
  ],
  "planning_note": "已按你的要求把「动态规划」相关知识点提前，但保留了必要的基础前置。"
}
```

**用户微调**：排序结果以列表形式展示，用户可**拖拽调整顺序**后再开始。调整后的顺序作为本次 session 的「知识点顺序快照」固化保存。

> **自定义提示词仅作用于此初始排序环节，一次性生效**。刷题过程中不再重新规划顺序。

### 4.3 多知识点题目的归属规则

一道题可能关联多个知识点。V3.0 规则：

- **题目归属到它的主知识点**（`question_knowledge.is_primary = 1`），只在该知识点的刷题中出现一次。
- 这样保证不会在多个知识点里重复刷到同一道题。
- 一道题若关联了尚未排序到的其他知识点，不做特殊拦截——主知识点决定它何时出现。

> **备选逻辑（不在 MVP 实现，仅记录）**：可改为「题目挂在其关联知识点中、按刷题顺序排得最靠后的那个」，确保做综合题前所有相关前置知识点都已练过。V3.0 先用 `is_primary` 主知识点归属，实现简单、语义清晰。

### 4.4 知识点内做题循环

**单题流程**：
```
展示题目（题干 + 选项/填空框）
  ↓
用户作答
  ↓
点击「提交」
  ↓
显示：答对/答错 + 正确答案 + 解析
  ↓
（可选）点击「问 AI」就本题某个点提问
  ↓
点击「下一题」 → 算法选出下一题
```

**选题策略（算法层）**：
- 正常模式：当前知识点题池内，**未做题优先**，按难度由易到难（结合掌握度动态调整）。
- 错题重刷模式：只从「本轮做错的题」中选题。
- 题池耗尽：触发「完成」流程。

### 4.5 知识点「完成」与推进

**完成条件**（满足任一）：
- 当前知识点 `mastery` 达到阈值（如 ≥ 0.8 且 `confidence` ≥ 0.7）
- 当前知识点题目全部做完

**完成后弹出选择**：

```
┌─────────────────────────────────────────────┐
│  ✅「循环结构」本轮完成                       │
│  本轮：12 题  正确率 75%  掌握度 0.82         │
│                                             │
│  [重新刷题]   [错题重刷]   [下一知识点 →]    │
└─────────────────────────────────────────────┘
```

- **重新刷题**：当前知识点全部题目重新刷一遍（清空本轮已做标记，掌握度延续）。
- **错题重刷**：仅重刷本轮做错的题。错题全部答对后再次触发完成选择。
- **下一知识点**：按顺序进入下一个知识点。

**提前推进**：用户在知识点未完成时也可随时点击「下一知识点」主动跳过，无需达成完成条件。跳过的知识点保留其当前进度，后续可回来继续。

## 5. 刷题页设计（核心页面）

单页三区布局，是 V3.0 的核心交互界面。

```
┌──────────────────────────────────────────────────────────────┐
│  ① 待刷知识点条（横向滚动）                                     │
│  ┌─变量与类型─┐ ┌─循环结构(当前)─┐ ┌─函数─┐ ┌─递归─┐          │
│  │ 8/8 ✓100% │ │ 5/12  60%      │ │ 0/10 │ │ 0/6  │          │
│  └───────────┘ └────────────────┘ └──────┘ └──────┘          │
├────────────────────────────────────┬─────────────────────────┤
│                                    │  ③ 掌握度分析面板        │
│  ② 做题区                          │                         │
│                                    │  当前知识点：循环结构     │
│  Q5. 以下关于 for 循环的说法...     │  掌握度 ████████░░ 0.82  │
│                                    │  置信度 ██████░░░░ 0.65  │
│  ○ A. ...                          │  连续答对 streak: +3     │
│  ● B. ...                          │                         │
│  ○ C. ...                          │  ── 全题库概览 ──         │
│  ○ D. ...                          │  变量与类型  ██████████  │
│                                    │  循环结构    ████████░░  │
│  [提交]                            │  函数        ░░░░░░░░░░  │
│                                    │  递归        ░░░░░░░░░░  │
│  （提交后）                         │                         │
│  ✓ 正确答案：B   你的答案：B ✓     │                         │
│  解析：for 循环适用于...            │                         │
│  [🤖 问 AI]      [下一题 →]        │                         │
└────────────────────────────────────┴─────────────────────────┘
```

### 5.1 区域 ①：待刷知识点条

- 横向排列所有知识点（按排序顺序），当前知识点高亮。
- 每个知识点卡片显示：
  - 知识点名称
  - **已做数 / 总题数**（如 `5/12`）
  - **正确率**（本轮答题正确率）
  - 完成状态标记（✓ / 进行中 / 未开始）
- 可点击已开始或已完成的知识点跳转回去（提前推进的逆操作）。

### 5.2 区域 ②：做题区

- **答题前**：题干 + 选项（单选/多选用按钮组，判断用是非，填空用输入框）。
- **提交按钮**：未选择时禁用。
- **提交后**：
  - 显示对错标识、正确答案、用户答案对比、解析。
  - 出现「问 AI」与「下一题」按钮。
- **问 AI**：点击后就本题弹出提问框（用户输入想不通的点，如「为什么不能选 C」），复用现有划词问 AI 的 LLM 能力。AI 解答展示在解析下方，并随答题记录持久化。

### 5.3 区域 ③：掌握度分析面板（算法驱动）

- **当前知识点掌握度**：
  - `mastery` 进度条（0~1）
  - `confidence` 进度条（0~1）
  - `streak` 连续答对/答错计数
- **全题库知识点概览**：
  - 所有知识点的掌握度小柱状图/进度条列表，反映整体进度。
- 所有数值由算法层实时计算，随每次提交即时刷新。

## 6. 掌握度算法

沿用 V2.0 的实时更新公式（客观题 score 为 0/1）。

### 6.1 用户能力模型

每个用户对每个知识点维护：

| 参数 | 范围 | 含义 |
|------|------|------|
| `mastery` | 0~1 | 掌握程度 |
| `confidence` | 0~1 | 系统对评估的置信度 |
| `streak` | 整数 | 连续正确(+)/错误(-)计数 |

### 6.2 更新公式

```typescript
// score: 客观题 0 或 1
// difficulty: 题目难度 0~1
// answerTime: 实际用时（秒）
// expectedTime: 预期用时（秒）

if (score >= 1) {
  // 答对
  const timeFactor = clamp(1 - answerTime / expectedTime, 0, 1)
  mastery += difficulty * 0.1 * (1 + timeFactor * 0.5)
  confidence += 0.15
  streak = streak > 0 ? streak + 1 : 1
} else {
  // 答错
  mastery -= difficulty * 0.12
  confidence += 0.10
  streak = streak < 0 ? streak - 1 : -1
}

mastery = clamp(mastery, 0, 1)
confidence = clamp(confidence, 0, 1)
```

> 错题重刷时的得分同样计入掌握度，但可标记 `is_retry` 以便报告区分。

## 7. 微学习（保留，不在主线）

微学习能力（知识点详解卡片 + 划词问 AI + 画布布局）在 V2.0 已实现并保留。V3.0 的主线是刷题，**不强制将微学习编入刷题闭环**。

- **保留入口**：用户在刷题页可手动为当前知识点打开微学习（如自觉某点薄弱时）。
- **不实现**：3.0 不做「知识点完成后自动引导进微学习再回刷题」的整合闭环。该整合作为后续迭代方向。

## 8. 数据库设计

### 8.1 复用现有表（V2.0 已实现）

`question_banks`、`questions`、`knowledge_points`、`question_knowledge`、`micro_learnings` 保持不变。其中 `question_knowledge.is_primary` 用于多知识点题目的主知识点归属。

### 8.2 新增表

**practice_sessions**（练习会话）：
```
id, bank_id,
knowledge_point_order(JSON: 用户确认后的知识点顺序快照),
current_kp_index(当前知识点在顺序中的位置),
custom_prompt(用户的自定义排序提示词，留存备查),
status(active / completed / paused),
started_at, ended_at, created_at, updated_at
```

**answer_records**（答题记录）：
```
id, session_id, question_id, knowledge_point_id,
user_answer, correct_answer, score(0/1),
time_spent(秒),
is_retry(0/1: 是否错题重刷轮次产生),
ai_question(用户对本题的提问，可空),
ai_answer(AI 解答，可空),
round_index(该知识点第几轮刷，用于区分重刷),
created_at
```

**user_mastery**（用户掌握度）：
```
id, bank_id, knowledge_point_id,
mastery, confidence, streak,
tested_count, correct_count,
last_updated
```

> 单题问 AI 的记录直接挂在 `answer_records` 上（`ai_question` / `ai_answer`），不另建表。一题多次提问的扩展场景留待后续。

## 9. API 设计概览

| API | 方法 | 说明 |
|-----|------|------|
| `/api/banks/[id]/graph` | GET | 获取知识图谱（已实现） |
| `/api/sessions` | POST | 创建练习 session（含调用排序规划） |
| `/api/sessions/[id]/plan` | POST | 生成/重排知识点顺序（输入自定义提示词） |
| `/api/sessions/[id]` | GET | 获取 session 状态（知识点顺序、进度、掌握度） |
| `/api/sessions/[id]/next-question` | GET | 在当前知识点取下一题（算法选题） |
| `/api/sessions/[id]/submit-answer` | POST | 提交单题答案，返回判分结果 + 更新后掌握度 |
| `/api/sessions/[id]/ask` | POST | 就当前题问 AI |
| `/api/sessions/[id]/advance` | POST | 知识点推进（重新刷题 / 错题重刷 / 下一知识点） |
| `/api/sessions/[id]/finish` | POST | 结束练习，生成报告 |
| `/api/mastery/[bankId]` | GET | 获取题库掌握度概览 |

## 10. 掌握度报告

练习结束（用户主动结束或全部知识点处理完）后生成。

**报告内容**：
- 各知识点掌握度柱状图（含本次变化幅度）
- 本次练习数据：总答题数、正确率、用时、涉及知识点数、错题重刷次数
- 薄弱知识点提示（mastery 未达阈值的知识点列表）

> V3.0 报告以算法数据为主，AI 总结为可选项（沿用 V2.0 思路，可后续接入）。

## 11. 实现分期

### Phase 1（V3.0 MVP）

- 选题库 → AI 知识点排序规划（含自定义提示词）→ 用户拖拽微调
- 刷题页三区布局（知识点条 / 做题区 / 掌握度面板）
- 仅客观题（单选 / 多选 / 判断 / 填空），系统比对判分
- 算法层选题 + 实时掌握度更新
- 单题「问 AI」
- 知识点完成判定 + 三选项推进（重新刷 / 错题重刷 / 下一知识点）+ 提前跳转
- 掌握度报告

### Phase 2（后续迭代）

- 主观题（简答 / 计算）LLM 判分
- 微学习整合进刷题闭环（薄弱知识点引导学习再回刷）
- 多知识点题目「最靠后知识点归属」备选逻辑
- AI 报告总结与学习建议
- 遗忘曲线 + 复习提醒

## 12. 核心产品指标

| 指标 | 目标 |
|------|------|
| 用户完成「选题库→刷完至少一个知识点」率 | > 70% |
| 知识点排序「符合我的需求」满意度 | > 4.0/5.0 |
| 单题「问 AI」使用率 | > 20% |
| 用户对刷题节奏掌控满意度 | > 4.2/5.0 |
| 刷题页交互流畅度（提交到反馈延迟） | < 200ms（纯算法，无 LLM） |

```
你是 PointMaster 学习路径规划助手。请根据题库的知识图谱，为用户规划一条合理的知识点刷题顺序。

## 知识图谱
{knowledge_graph_json}   // 知识点列表 + 各自的 prerequisite_ids

## 用户的自定义要求（可能为空）
{custom_prompt}          // 如「我想优先刷动态规划」

## 排序原则
1. 必须遵守知识点依赖关系：前置知识点排在依赖它的知识点之前。
2. 在不破坏依赖的前提下，尽量满足用户的自定义要求（软约束）。
3. 为每个知识点给出一句简短的排序理由。

请输出 JSON：
{
  "ordered_knowledge_points": [
    { "id": "...", "name": "...", "order": 1, "reason": "..." }
  ],
  "planning_note": "一句话总结你的排序思路，特别说明如何处理了用户的自定义要求"
}
```
